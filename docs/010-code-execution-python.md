## オフライン挙動の調査メモ（2026-06-20）

### 現状の仕組み

- Pyodide は実行のたびに CDN（`cdn.jsdelivr.net/pyodide/v0.26.2/`）から読み込む（`lib/code-execution/sandbox.ts`）。
- WebView は `source={{ html, baseUrl }}` でインライン HTML を毎回ロードするだけで、**アプリ側で Pyodide を保存する処理は無い**（`components/code/ExecutionOutput.tsx`）。
- 「2回目以降オフラインで動く」のは **OS（WKWebView / NSURLCache）の HTTP キャッシュ任せ**。jsdelivr が長期キャッシュヘッダ（`immutable` 等）を付けるため、結果的にキャッシュに残って動くことが多い、という挙動。

### キャッシュの有効期間（よくある疑問への回答）

- **アプリ終了・再起動はまたいで残る**（ディスクキャッシュのため）。
- **アプリ削除で確実に消える**が、**削除前でも OS がストレージ逼迫時などに自動破棄(evict)し得る**。
- → 「初回さえ DL すれば永久にオフライン OK」ではなく、**保証されないベストエフォート**。
- キャッシュ消失後にオフライン実行すると `sandbox.ts` の「Pyodide の読み込みに失敗しました（インターネット接続を確認してください）」エラーになる（グレースフルに失敗）。

### 完全オフライン対応の選択肢と評価

費用対効果は薄く、**当面は現状維持**でよいと判断（実害が少なく、失敗時も明示エラー）。対応するなら以下：

- **案A：バイナリ同梱** — アプリサイズ +13〜15MB（`pyodide.asm.wasm` 約9MB＋`python_stdlib` 約4MB＋JS）。`micropip` 追加パッケージは結局 CDN 依存のまま残るため「完全オフライン」は中途半端。バージョン更新の再同梱メンテ＋ WKWebView の `file://` ローカル wasm 読み込み設定が面倒。→ **非推奨。**
- **案B：任意ダウンロード方式（推奨）** — 設定にトグルを置き、オンライン時に Pyodide 一式を `documentDirectory` へ自分でダウンロード保存し、以後は `file://`（`baseUrl`）から読む。
  - 利点：アプリサイズは増えない（必要な人だけ取得）／OS の eviction を受けず自分が消すまで永続（現状の弱点を解消）／jsdelivr 障害にも強い。
  - 工数は案A より少し多いが、「サイズ増 vs 不確実なキャッシュ」の両方を同時に潰せる。

### 進め方

1. 当面は現状維持。
2. オフラインでの Python 実行ニーズが実際に出てきたら、**案B（任意ダウンロードトグル）** を実装する。
