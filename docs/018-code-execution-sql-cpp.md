## SQL 初期化SQL（加算型ハイブリッド）

### 目的

SQL のフラッシュカードでは「`SELECT` の構文だけを問いたい」のに、毎回お膳立ての `CREATE TABLE` / `INSERT` をカード本文に書かねばならない問題がある。これを解消するため、**実行するクエリ本体とは別に、事前に流す初期化SQL（スキーマ＋初期データ）**を持てるようにする。

### モデル：加算型ハイブリッド

初期化SQLを 2 階層で持つ。

1. **デッキ共通の初期化SQL**（`Deck.sqlInit`）— そのデッキの全カードで共有する土台（例: `users` テーブル）。
2. **ブロック固有の初期化SQL**（`CodeBlock.sqlInit`）— その SQL コードブロックだけで使う追加分（例: そのカード専用の `orders` テーブル）。

実行時は次の順で**同じ DB インスタンス**に対して流す（加算）。

```
[デッキ共通の初期化SQL]   ← 常に実行（空ならスキップ）
        ↓ 続けて
[ブロック固有の初期化SQL]  ← あれば追加実行（空ならスキップ）
        ↓ 続けて
[クエリ本体（ブロックの content）]  ← この結果だけを表示
        ↓
DB 破棄
```

- **リセット型**：実行のたびに `new SQL.Database()` でまっさらから作り直す。あるカードの `INSERT`/`DELETE` は他カードに残らない。何度学習しても同じ初期状態から始まる（フラッシュカードの反復に必要な冪等性）。
- **加算であって上書きではない**：ブロック固有があってもデッキ共通は無視されず、土台の上に積まれる。これにより共通テーブルを毎回コピペせずに済む。
- **両方とも任意（空可）**：
  - デッキ共通のみ → 全カードが共通テーブルで練習
  - ブロック固有のみ（デッキ共通は空）→ カードごとに独立したテーブル
  - 両方 → 共通テーブル ＋ カード固有の追加
  - 両方空 → 初期化なし（`SELECT 1+1` などの単発クエリ）
- **同名テーブルの衝突**：共通と同名・別構造のテーブルをカード側で作りたいレアケースは、ブロック固有の先頭に `DROP TABLE IF EXISTS xxx;` を書いて回避する（標準動作は加算のまま）。

### エラーの扱い

初期化SQL（デッキ共通／ブロック固有）の実行で例外が出た場合は、ユーザーのクエリ本体のエラーと区別するため `初期化SQLでエラー: ...` の接頭辞を付けてメッセージを返す。クエリ本体のエラーは従来どおり。

### データ／実装方針

- **型**：`Deck.sqlInit: string | null`、`CodeBlock.sqlInit?: string`。
- **DB**：`decks` に `sqlInit TEXT`（nullable）を `ALTER TABLE` で追加。ブロック固有は `card_contents` の JSON にそのまま含まれる（マイグレーション不要）。
- **`Deck.language` は無関係**：`language` は人間言語（現状 `'ja'` 固定・未使用の名残）であり、プログラミング言語ではない。「SQLデッキ」という区別は存在しないため、デッキ共通初期化SQL欄はデッキ編集画面の任意項目として常設する。
- **実行系**：`buildSqlSandboxHtml(code, initSqls?)` が `initSqls`（順序付き配列）を本体の前に黙って実行する。`useCodeExecution.run()` と `CodeRunnerView` 経由でデッキの `sqlInit` とブロックの `sqlInit` を渡す。学習画面・エディタプレビューともデッキIDからデッキの `sqlInit` を取得してスレッドする。
- **UI**：デッキ編集／新規画面に「SQL 共通初期化」欄、`CodeBlockItem`（SQL ブロック時のみ）に「初期化SQL」折りたたみ欄を置く。
- **Pro ゲート**：SQL は `PRO_LANGUAGES` の Pro 機能のため、初期化SQL の入力欄（デッキ編集／新規・コードブロック）はいずれも `isPro` のときだけ表示する（非Proはそもそも SQL を実行できず、デッキ編集画面は全ユーザーが見るため）。買い切りで失効しないため「Pro時に設定→消える」事故はなく、データは DB に保持される。
