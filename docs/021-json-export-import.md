## 画像対応エクスポート/インポート

現状の実装では画像ブロックの `uri`（`local://images/xxx.jpg`）はパス文字列のみ保存されており、
画像ファイル本体はエクスポートに含まれない。そのため別端末へのインポートや、
画像削除後の復元ができない。以下の機能を追加実装する。

### Todo

- [x] **Base64埋め込み対応**: エクスポート時に画像ファイルを読み込みBase64文字列としてJSONに含める。インポート時はBase64をデコードして `images/` ディレクトリにファイルとして書き出す。
- [x] **画像含む/含まない選択UI**: エクスポート実行時に「画像を含める（完全バックアップ）／含めない（軽量バックアップ）」を選択できるようにする。「含めない」を選んだ場合は別端末では画像が表示されない旨を警告する。
- [x] **大容量警告**: 画像を含めてエクスポートする際、推定ファイルサイズに応じて2段階の確認ダイアログを表示する。
  - 10MB超〜50MB以下: 「約○MBになります。続けますか？」
  - 50MB超: 「約○MBになります。レスポンスに影響が出る可能性があります。続けますか？」

### 設計メモ
- Base64はバイナリの約1.33倍のサイズになる。1枚5MB上限のため1枚あたり最大約6.7MB相当。
- SQLiteには引き続きパス文字列のみ保存する（Base64をDBに入れない）。
- エクスポートJSONの `ExportData` に `imageData?: Record<string, string>`（キー: ファイル名、値: Base64）フィールドを追加する形が考えられる。

## 将来検討: CSVエクスポート/インポート

Numbers / Excel / Google スプレッドシートとの連携を目的とした機能。
JSON実装後に需要を確認してから着手する。

### 設計メモ
- 列構成: `deck_name, front, back, memo, tags`
- `front`/`back`/`memo` は**テキストブロックのみ**結合して出力（コード・画像は対象外）
- インポートでは各行を「テキストブロック1つのカード」として作成
- `tags` 列はセミコロン区切り（例: `Swift;基礎`）
- 学習履歴（SM-2データ）はCSVに含めない

### 制約・注意
- コードブロック・画像ブロックはCSV出力時にデータが失われる
- 学習履歴はCSVに含まれないため、インポート後は未学習状態になる
- CSVインポートはテキストカードの一括作成用途に限定する
