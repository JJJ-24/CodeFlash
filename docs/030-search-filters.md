## 設計メモ

- デッキ・タグともに複数選択 OR（いずれかに一致）で絞り込む
- AND 検索（すべてのタグを含む）は実装コストが高いわりにユースケースが限定的なため未実装
- `MultiSelectPickerModal`（タグ用）は `PickerItem = { id, name, color? }` の汎用型で設計。将来的に他のフィルター（習熟度など）にも流用可能
- 検索クエリが空のとき、デッキ・タグだけでは結果を表示しない（クエリ必須）。
  **例外は Phase 2 の学習日フィルターだけ**（下記）
- ピッカーはタップでトグル選択し「完了」ボタンで閉じる方式（従来の単一選択＋即閉じ方式から変更）

## Phase 2: 学習した日フィルター ＝**完了（2026-08-25・実機確認済み）**

「昨日学習したカードをもう一度見たい」「おととい何をやったか振り返りたい」に応える。
検索画面は既に**全デッキ横断でカードを探す**場所なので、「昨日 A デッキで学習したカード」が
デッキ絞り込みとの掛け合わせでそのまま表現できる。新しい画面もシートも作らない。

### 確定仕様（設計合意・2026-08-25）

| 論点 | 決定 |
|---|---|
| 粒度 | **1日単位**（範囲指定にしない） |
| 文字クエリ | **空でも検索する**（学習日が指定されていれば） |
| デッキ/タグ単独 | **従来どおり検索しない**（それはデッキ詳細画面の役目） |
| 並び順 | 学習日指定時は**その日の学習が新しい順**。通常検索は `updatedAt DESC` のまま |
| 取得上限 | 学習日指定時は **1000件**（`SEARCH_DATE_RESULT_LIMIT`）。通常検索は 100 のまま |
| アーカイブ | **含める**（過去実績なので `activeCardCond` は掛けない規約どおり） |
| UI | タイトル行に3つ目のアイコン（カレンダー）＝押すと今日で ON。チップに `◀ 日付 ▶ ×` |
| 日付の直接指定 | チップの**日付部分をタップ**でカレンダー（`DateTimePicker` の `display="inline"`） |
| キー | `R`（Reviewed）= ON/OFF、`⇧,`/`⇧.`・`⇧H`/`⇧L` = 前日/翌日（カレンダーを開くキーは割り当てない） |

### なぜ「1日単位」なのか（範囲チップを不採用にした理由）

当初は相対チップ（今日／昨日／7日以内／30日以内）を提案したが、3つの問題で破綻した。

1. **件数** — 1日20枚でも30日で600枚。100件上限とは根本的に相性が悪い
2. **統計の棒グラフと対応しない** — 棒は1本＝1日なので、将来「棒をタップして検索を開く」
   導線を足すとき、**おととい・3日前を表現する選択肢が無い**（7本中2本しか対応できない）
3. **言葉と合わない** — ユーザーの言い方が「昨日学習したカード」＝そもそも1日単位

1日単位ならこの3つが同時に解ける。件数は人間の1日の学習量に自然に収まり、棒グラフとは 1:1 で
対応し、日送り `◀ ▶` で「おととい」「3日前」にも数タップで届く。

### なぜ並び順を変えるのか

⚠️ **`cards.updatedAt` は学習では更新されない**（`saveReview` が書くのは `reviews` /
`review_logs` / `grade_logs` だけ）。そのため学習日で絞った結果を `updatedAt DESC` で並べると
**「最近編集した順」＝学習とは無関係な順序**になり、上限で切れるときに落ちるカードも
学習の新旧と無関係に決まる。

`grade_logs` は「カード×日で1行・その日の最後の評価」を保つ作り（同日の再評価は DELETE→INSERT）
なので、そこから時刻が取れる。024 より前の記録には行が無く NULL になるが、SQLite は NULL が
最小＝DESC で末尾に回る（末尾に古い記録が並ぶだけで壊れない）。

### なぜ上限を別建てにするのか

文字検索の 100 件は「**クエリを絞り込め**」という促しとして機能している（「あ」で検索して
全部出しても意味がない）。一方、学習日の結果は「その日に学習した全部」＝**有限で、それ自体が答え**。
日付はもう最小単位なのでユーザーには絞り込む手立てが無く、100 で切ると必ず取りこぼす。

⚠️ **ページング（「次のカードへ」ボタン）は不採用**：上限を 1000 にすれば発生しない状況
（1日1000枚超）のために、オフセット状態・フィルター変更時のリセット・追記後の J/K フォーカス
維持・ボタン自体をフォーカス対象にするかの判断が増える。034 のショートカットとフォーカス追跡で
既に複雑な画面なので割に合わない。1枚10秒でも1時間で360枚＝1000は人間の1日の上限を超えている。
無制限にしないのは、インポート等で同じ日付に大量の記録が入ったときに固まらないため。

### カレンダー（日付の直接指定）

日送り `◀ ▶` は「昨日・おととい」には最短だが、先月の特定の日には届かない。チップの
**日付部分をタップ**すると `DateTimePicker`（`mode="date"` / `display="inline"` ＝ iOS の
カレンダー UI）をシートで開く。通知の時刻ピッカーと同じライブラリ。

- **日付を選んだ時点で確定して閉じる**＝カレンダーで日を押すのはそれ自体が確定操作で、
  ［完了］を挟むと1タップ増えるだけ
- `maximumDate` を今日にする（未来の日付に学習記録は存在しえない＝チップの ▶ が今日で
  止まるのと同じ制限をピッカー側にも掛ける）
- 色は `themeVariant`（⚠️ `Appearance.setColorScheme()` は使わない方針＝CLAUDE.md）
- **カレンダーを開くキーは割り当てない**：ネイティブの UI なのでアプリ側からキー操作を
  渡せず、開いても矢印で日を選べない。ハードキーボードでは `⇧,`/`⇧.` の日送りで足りる。
  ただし**表示中は背景のキーを止める**（`overlayOpen()` に追加）＋ Esc で閉じる
  （デッキ/タグのピッカーと違い自前の Esc を持てないので、親の Esc 階層で処理する）
- ⚠️ `A`（カード統計シート）の早期 return にも `datePickerVisible` を足す：許すと
  **RN Modal が2枚同時**になり、iOS は同じ VC から2枚目を提示できず**提示状態が固着して
  画面がタップを受け付けなくなる**（CLAUDE.md「Modal を2枚重ねるときは入れ子にする」）

### 統計の棒グラフからの導線（Phase 3・実装済み）

「過去7日間の学習済み」の棒をタップ → その日付フィルターで検索画面を開く（棒＝1日なので
7本すべてが対応する）。**一覧の実装は検索画面のものを再利用**するので、同じ一覧が2箇所に
存在することにならない。逆順（先に専用シートを作る）だと重複する。

**戻る導線は作らなくてよい**：`app/search.tsx` は `(tabs)` の上に push される root Stack の
画面で、閉じる操作（FAB・ヘッダー・`B`・Esc）はすべて `router.back()`。タブはアンマウント
されないので、統計タブから開けば**閉じるだけで統計タブへ戻る**。⚠️ CLAUDE.md の旧記述
「`B` = 戻る（ホーム）」は入口がホームだけだった名残で、実装はホーム固定ではない。

⚠️ **ただし「戻ったら上部ブロックが初期フィルターに化ける」既存バグを踏む**（初期フィルター
＝復習のとき、済みの棒から検索へ行って戻ると復習になる）。統計タブの `useFocusEffect` が
`initialFilterPreference` を**フォーカスのたびに**再適用していたため。初期フィルターは
「**タブに入ったとき**」の設定であって、自分が開いた子画面から戻ったときに適用するものでは
ない（ユーザーはその場所を離れていない）。学習タブが `fromSessionRef` で既に解いていたので
同じ流儀に揃え、統計タブは `pushChild()`（`router.push` のラッパー＝印を付けて push）を
経由させる。**この画面から push するときは必ず `pushChild` を通す**。検索だけでなく
苦手カードの編集・重点復習・Pro 案内からの戻りも同じ症状だったので、6箇所すべてに適用した。

**押せるのは「済み」ブロックの棒だけ**（`onSelectDate` をそのときだけ渡す）。上部ブロックの
選択でグラフの中身が入れ替わるため、棒の意味が4通りあり、対応するのは1つしかない。

| ブロック | 棒の中身 | 押せるか |
|---|---|---|
| 済み | `review_logs` のその日の枚数 | **○**（棒の数字＝結果の件数） |
| 連続 | 同じデータの 0/1 | ✕ 棒は 1、結果は N 件で数字が一致しない |
| 復習 | **未来**の予定枚数 | ✕ 学習記録が存在しえない（カレンダーも `maximumDate`＝今日） |
| 新規 | `cards.createdAt` の作成枚数 | ✕ 別軸（検索に作成日フィルターは無い） |

⚠️ **0枚の日も押せなくする**（`item.count > 0`）＝開いても空の結果にしかならない。押下時の
`opacity` も出さない＝「押せる見た目なのに何も起きない」を作らない（月別グラフと同じ流儀）。

**棒に押せる見た目は与えない**ので、気づける場所はセクションの ⓘ しかない。`goalLineInfoMessage`
と同じく**「済み」を見ているときだけ** `barTapInfoMessage` を継ぎ足す（他のブロックを見ている
間に、画面に無い操作の説明を出さないため）。

検索画面側は `studiedDate` パラメータを受けて2点だけ変える。

- ⚠️ **セッション復元をしない**（`store/search.ts` の query/deckIds/tagIds をクリアし、日付だけ
  入れた素の状態で開く）＝前回の絞り込みが残ると**「棒の数字 42」と「結果 3件」が食い違い**、
  原因が画面から読めない。棒からの遷移では常に「棒の数字＝件数」が成り立つようにする
- ⚠️ **自動フォーカスしない**＝`query` が空でも学習日フィルターがあれば結果は出ているので、
  ソフトキーボードが結果一覧を覆ってしまう（判定を `query` だけでなく `studiedDate` にも広げた
  ので、ホームから開いて日付が復元されたときも同じ扱いになる）
