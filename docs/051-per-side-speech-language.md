# 051 読み上げの面ごとの言語（表面／裏面）＋デッキ設定の Pro 化

**フェーズ:** 将来
**ステータス:** 完了（Phase 1〜3・2026-09-02・実機確認済み／設計合意 2026-09-01）
**要ネイティブ再ビルド:** 不要（`expo-speech` は導入済み・DB 列の追加のみ）
**依存:** 049（読み上げ本体）・050（Phase 2＝デッキ単位の上書き）
**被依存:** なし

---

## 概要

**両面が同じ文字体系で、言語だけが違うデッキ**を読み分けられるようにする。

```
いま（050 Phase 2）  デッキ → 文字体系ごとの言語（1デッキ1マップ）
本チケット           デッキ → 表面用のマップ ／ 裏面用のマップ
```

想定は **英語 ⇄ スペイン語の単語帳**のような組み合わせ。表も裏もラテン文字なので、
文字体系による分割では原理的に分けられず、デッキ単位の上書きも1マップしか持てないため
「表は英語・裏はスペイン語」を表現できない。**面**という外形的な手掛かりで分ける。

日本語 ⇄ スペイン語のように**文字体系が違う**組み合わせは 049/050 で既に自動で分かれるので、
本チケットの対象外（設定なしで読み分く現状を維持する）。

---

## 050 の「面単位は不採用」との関係（前提の訂正）

050 は「カード単位・面単位の言語設定」を**不採用**と記録している。3つの理由のうち **1 が誤り**で、
2・3 は今回の案には当たらない。

| 050 の理由 | 051 での扱い |
|---|---|
| 1. 面単位が要るのは表=英語/裏=スペイン語のときだけで、**それはデッキ単位で埋まる** | **誤り**。デッキ単位は1デッキ1マップなので、**両面が同じ文字体系のデッキは埋まらない**。埋まるのは「デッキごとに言語が違う」場合だけだった |
| 2. カードごとの指定は運用コストがユーザーに乗る（1000枚に手作業） | **当たらない**。今回は**デッキ × 面**＝設定は1デッキにつき最大2回で、カードは1枚も触らない |
| 3. 1面の中の混在（`React の useEffect は…`）は面単位では解決しない | **変わらず正しい**。面の設定は「その面のラテン文字を何語で読むか」だけを決め、**1面の中の分割は従来どおり文字体系が担当する** |

したがって **カード単位は引き続き不採用**、**デッキ × 面だけを採る**。

## 確定仕様（設計合意・2026-09-01）

| 論点 | 決定 |
|---|---|
| 粒度 | **デッキ × 面（表／裏）**。カード単位はやらない |
| 保存 | `decks.speechLangsBack`＝裏面用の `ScriptLangs`（JSON・`ALTER TABLE` で追加・未設定は NULL） |
| 未設定の意味 | **表面と同じ**（＝既存デッキの挙動は完全に不変） |
| メモ面 | **裏面に従う**（今回は分けない。将来の検討事項として下に条件を残す） |
| 解決順 | デッキ（その面） → アプリ設定 → 文字体系の既定。`mergeScriptLangs` も解決の中身も**無改造** |
| 声 | **デッキに持たせない**（050 の判断を踏襲＝identifier は端末固有） |
| Pro ゲート | **デッキに保存する読み上げ設定を Pro**（既存のデッキ別言語＋今回の表裏をセットで）。⚠️ **適用は通す・設定 UI だけ塞ぐ・解除は非 Pro でも可** |
| UI | `DeckSpeechModal` に「裏面を別の言語で読む」トグル。**ON のときだけ**裏面用の一覧を出す |

## 設計

### 1. データと解決

```ts
// types/index.ts
speechLangsBack: ScriptLangs;   // 空 = 表面と同じ

// app/study/session.tsx（1行）
const deckSpeechLangs = isFlipped
  ? (deck.speechLangsBack ?? {}) が空 ? deck.speechLangs : deck.speechLangsBack
  : deck.speechLangs;
const speech = useSpeech(deckSpeechLangs);
```

`useSpeech` は `ScriptLangs` を1つ受け取るだけの作りなので、**渡すマップを面で選ぶだけ**で足りる。
`splitByScript` → 言語解決 → 畳み込みの本体（`lib/speech.ts`）には一切触らない。

⚠️ **渡すのは「いま読むカードの所属デッキ」の値**（タグ学習は1セッションに複数デッキが混ざる）。
050 Phase 2・044/045 の土台・043 の画像ライブラリと同じ引き方に揃える。

⚠️ **「裏面が空 = 表面と同じ」の判定は空オブジェクトで行う**（`?? {}` だけでは既定に落ちない）。
`Object.keys(...).length === 0` を1か所（`lib/speech.ts` にヘルパを置く）に閉じ込め、
画面側で毎回書かない。

### 2. メモは裏面に従う（今回は分けない）

学習画面は裏面表示中にメモを開くと **`[裏面, メモ]` を繋いだ1本のテキスト**を読む
（`session.tsx` の `speechText`）。面ごとに1マップなので、メモだけ別言語にはできない。

- メモに**日本語の解説**を書いている場合は、かな漢字なので自動的に日本語で読まれる＝実害なし
- メモを**ローマ字や英語**で書いている場合は、裏面の言語（例：スペイン語）で読まれる

将来メモを独立させるなら、**テキストを1本に繋ぐのをやめて発話を2本に分ける**必要がある
（`speakText` を面ごとに2回積む／`speaking` の完了判定を最後の面の `onDone` に寄せる）。
UI も3セットに増えるので、要望が出てから判断する。

### 3. Pro ゲートの深さ

**設定 UI だけ Pro・適用は通す**。HTML 土台で「非 Pro には積まない」としたのは、積むと
**可視プレビューという Pro 機能そのものが漏れる**からだが、読み上げにはその構造が無い
（読み上げ自体が無料なので、デッキ設定を適用しても漏れる能力が無い）。適用を止めると、
配布・iCloud で受け取ったデッキが**作者の意図と違う言語で読まれる**だけで誰も得しない。

⚠️ **「解除（クリア）」は非 Pro にも許す。** これが無いと、インポートや同期で設定済みデッキを
受け取った非 Pro ユーザーが、**その言語で読まれるのを直す手段を画面から失う**（デッキ設定は
アプリ設定に勝つため、アプリ側からは打ち消せない）。「見る・消すは無料／設定するのは Pro」なら
CLAUDE.md の「画面から変えられない状態を作らない」に反しない。

⚠️ **Pro 化はリリース前に必ず入れる。** 049/050 は未リリース（v1.10.1 は 2026-08-09、読み上げの
実装は 8/20〜8/30）なので、いま Pro にしても**取り上げにはならない**。無料で出したあとに
有料化するのは事実上できない一方、Pro で出して後から無料開放はいつでも安全にできる。

⚠️ この決定は **050 と CLAUDE.md の「Pro ゲートは付けない（読み上げは無料機能）」を意図的に
反転する**。実装時に両方の記述を更新すること（読み上げ本体・アプリ全体の設定・声・速度は**無料のまま**で、
Pro になるのは**デッキに保存する設定だけ**）。

### 4. UI

`DeckSpeechModal` の先頭に **「裏面を別の言語で読む」トグル**（既定 OFF）を置き、ON のときだけ
裏面用の一覧を続けて出す。

⚠️ **[表面|裏面] のセグメントで常時2面にしない。** このシートは文字体系ごとに「言語／混在文では
声を分けない／声」の3行を持つため、常時2セットにすると縦を食い尽くす。OFF が既定なら
**現状の見た目は1ミリも変わらない**。

デッキ編集の行のサマリー（`deckSpeechSummary`）は「表:英語／裏:スペイン語」の形に拡張する。
非 Pro では行に鍵アイコンを出し、タップで paywall へ（ただし**設定済みなら解除だけはできる**）。

### 5. 往復（エクスポート・インポート・TSV・iCloud）

- JSON エクスポートは `SELECT *` なので**自動**
- インポートは `import.ts` の列リストに1つ足すだけ（051 以前のファイルは NULL＝未設定に吸収）
- TSV は往復しないので `inspectTsvExport` の `deckSpeechLangs` の件数に裏面ぶんも数える
- iCloud は DB ファイルごと往復するので追加対応なし。**旧バージョンのアプリは新列を無視するだけ**
  （044/045 の旧列ミラーのような仕掛けは不要＝表面の設定は既存列のまま残るので、旧バージョンでも
  表面の読み上げは今までどおり動く）

### 6. 表裏の判定は `isFlipped`

全画面モードも閲覧モード（`browse=1`）も同じ state を見ているので、追加の分岐は要らない。
読み上げ FAB が読むのは常に「いま表示している面」で、この定義は 049 から変わらない。

## 不採用（再提案しないこと）

### カード単位の言語設定

050 の判断を維持する（1000枚のデッキに手作業は現実的でなく、新規カードのたびに指定が要る＝
「何も設定せずに読める」という本来の要求と逆向き）。

### 適用まで Pro で止める

配布・同期で受け取ったデッキが作者の意図と違う言語で読まれるだけで、**止めても守られる Pro 機能が
無い**（読み上げ自体が無料）。上の「ゲートの深さ」参照。

### 表/裏をセグメントで常時2面出す

シートの縦を食う。既定 OFF のトグルなら、表裏を分けないデッキの見た目と操作は現状のまま。

### 統計的・辞書的な言語自動判定

049/050 と同じ理由で不採用。同じラテン文字を共有する言語同士は原理的に区別できず、短文では
精度も出ない。**面という外形的な手掛かりで分けるのが本チケットの要点**。
