# 053 設定の詳細画面のキーボード操作

**フェーズ:** Phase 1（共通の仕組み＋表示）→ Phase 2 以降（1画面ずつ）
**ステータス:** Phase 1・2・3 完了（実機確認済み 2026-09-25）／Phase 4 未着手
**要ネイティブ再ビルド:** 不要（JS のみ）
**依存:** 034（ネイティブ UIKeyCommand）
**被依存:** なし

---

## 概要

設定タブの一覧は J/K（フォーカス）と Return（開く）に対応済み、詳細画面は Esc/B（戻る）だけに
対応している。詳細画面の**中の設定項目**もキーボードで操作できるようにする。

対象の詳細画面は6つ：表示・学習・通知・iCloud 同期・データ・同期の復元（`app/settings/*.tsx`）。
**表示画面から1画面ずつ**進める。

---

## 方針転換（CLAUDE.md の更新が要る）

CLAUDE.md の設定タブの項に「**値の変更はタップ限定（誤操作防止）でキーはナビのみ**」とある。
本チケットで**詳細画面ではキーで値を変えられる**ようにする。

- 誤操作の心配は小さい：**フォーカス（青枠）を当ててから押す2段階**で、押す対象が画面に見えている。
- **設定タブの一覧は従来どおりナビのみ**（一覧には値を変える部品が無い）。
- Phase 1 の完了時に CLAUDE.md の該当箇所を書き換える。

## 共通の操作（全詳細画面）

| キー | 動作 |
|---|---|
| `J` / `K`・`↓` / `↑` | カード（設定項目）単位のフォーカス移動。ヌルサイクル（末尾の次はフォーカスなし）。青枠＋画面外なら自動スクロール（設定タブと同じ見た目） |
| `H` / `L`・`,` / `.`・`←` / `→` | フォーカス中の項目の値を左右に動かす（項目が左右を持つときだけ） |
| `1`〜`n` | フォーカス中の選択肢型の項目で直接選ぶ（上部ブロックのフィルター 1〜4 と同じ流儀） |
| `Return` | フォーカス中の項目を**開く**＝一覧・スライダー・シートを開く・折りたたみ開閉 |
| `Space` | フォーカス中の**スイッチの ON/OFF**（Phase 3 で Return と分けた） |
| `Esc` | インライン説明（escStack）→ **フォーカス解除** → 戻る（設定タブと同じ「フォーカスがあれば外す」） |
| `B` | 戻る（従来どおり直接戻る） |
| `?` | ショートカット一覧（詳細画面ごとの一覧を新設） |

- **矢印は iPad でも登録する**（詳細画面に文字の入力欄が無い＝CLAUDE.md の「編集が無い画面は両方で登録」）。
  ⚠️ 入力欄を持つ詳細画面が出てきたら、その画面だけ iPhone のみ登録に落とす（学習セッション・エディタと同じ扱い）。
- **フォーカスが無いときは H/L・数字・Return/Space は何もしない。**

## 表示画面（Phase 1）

| 項目 | 部品 | 操作 |
|---|---|---|
| テーマ | `SegmentedCard`（3択） | H/L 等で左右・`1`/`2`/`3` で直接 |
| 文字サイズ | 同上 | 同上 |
| 初期フィルター | 同上（ⓘ あり） | 同上。ⓘ はタップのみ（「ⓘ＝指の操作」の規約） |
| 表示言語 | 行 → `LanguagePickerModal` | `Return` で開く → 一覧内は `J`/`K` で移動・`Return`/`Space` で選んで閉じる・`Esc` で閉じる（`DeckPickerModal` と同じ単一選択の流儀） |
| カラーテーマ | 横スクロールの見本 | H/L 等で左右。選択中の見本が見えるよう横スクロールを追従させる |
| キーボード | トグル（`AppSwitch`） | `Space` で切替（Phase 3 で Return を外した） |

## 学習画面（Phase 2・2026-09-25 合意）

### フォーカスは1段（セクションの見出しも中の項目も1本の列）

- **J/K は見出しと中の項目を上から順に1本の列として移動**する。見出しで `Return` ＝折りたたみ開閉。
- **`⇧J` / `⇧K` ＝前後のセクション見出しへ跳ぶ**（4セクションの間を速く動く）。**端では反対の端の見出しへ巡回する**（J/K と揃える。ただし J/K と違い「フォーカスなし」は挟まない＝外すのは Esc）。
- **折りたたんだセクションの中身は飛ばす**（描画されない＝登録されない）。折りたたみは保存されるので、
  使わないセクションを閉じておけば J/K の数が自然に減る。
- フォーカスの枠は**カードではなく行**に付く（青枠は行の外側に少しはみ出して描く）。

**2段（セクション → Return で中へ → 項目）は不採用**：①今どちらの段にいるかを見た目で示す必要がある
②Esc の意味が段で変わる（段を戻る／フォーカス解除／画面を戻る）③表示画面・統計タブ（草グラフ・デッキ・
月別・ランキングを1列で移動）と揃わない。セクション間を速く動く利点は `⇧J`/`⇧K` で取り込む。

### スライダーの項目は行にフォーカスしたまま H/L で動かす

- `H`/`L`（`,`/`.`・`←`/`→`）＝1目盛り、**`⇧H`/`⇧L`（`⇧,`/`⇧.`・`⇧←`/`⇧→`）＝大きく**（行の数字がその場で変わる）。
- `Return` ＝従来どおりスライダーのダイアログを開く。**ダイアログの中でも** H/L・⇧H/⇧L・←/→ が効く。
- 大きい刻みは項目ごと（範囲の約1/10）：目標枚数 10・読み上げ速度 0.25・目標保持率 5%・学習時間 5分・
  繰り返し回数 2回・休憩 5分。
- **読み上げの速度は1フォーカスにまとめる**：H/L＝0.05 刻み・`1`/`2`/`3`＝遅い/標準/速いのプリセット。
- **FSRS のプリセットは独立した3択の項目**（保持率の行と別）＝プリセットと保持率は同じ値の別表現だが、
  保持率の行は ⓘ を持ち、タップでもそれぞれ別の部品なので揃える。

### 試聴は `S`

- 読み上げの速度の ▶、声の一覧の各行の ▶ ＝ `S`（学習画面の `S`＝読み上げ/停止と同じ文字）。
- 声の一覧は **`Return`/`Space` ＝選んで閉じる／`S` ＝フォーカス中の声を試聴**（聞き比べで誤って選ばない）。

### その他の行

| 行 | 操作 |
|---|---|
| トグル（有効化・声を分けない） | `Space`（Phase 3 で Return を外した） |
| 3択（達成時の動作・円/残り時間・終了時の動作・FSRS プリセット） | H/L 等（端で止める）・`1`〜`3` |
| 自動読み上げ・文字体系の言語・声 | `Return` で一覧 → 一覧の中は J/K・`Return`/`Space`（選んで閉じる）・Esc |
| 「その他の文字体系」 | `Return` で開閉 |
| Pro のロック（FSRS・タイマーのカード・自動読み上げ） | `Return` で paywall（タップと同じ） |
| ⓘ | タップのみ（「ⓘ＝指の操作」の規約） |

- 数字キーはセクションへの直接移動には使わない（3択の直接選択に使う）。
- 目標 OFF の確認ダイアログ（`ConfirmModal`）の表示中は、背後の項目操作を止める（`SettingsDetail` の `blockNav`）。
  Esc はダイアログを閉じる（＝キャンセル）。削除系と同じく `Return` は割り当てない。

### 実装：行単位のフォーカス（Phase 1 の仕組みの拡張）

Phase 1 は「`SettingsDetail` 直下の要素の y」をそのままスクロール位置に使っていた。学習画面は
カードの**中の**行にフォーカスするので、`SettingsFocusGroup`（カード等）が自分の y を子へ渡し、
項目は「親の y ＋自分の y」で位置を出す（入れ子にできる＝文字体系の行のまとまりの中の行）。
`measureLayout` は使わない（ScrollView の中身の座標とスクロール量の扱いが Fabric で読みにくいため）。

## 通知画面（Phase 3・2026-09-25 合意）

### トグルは Space だけ（全詳細画面で統一・表示/学習もそろえる）

- **Space＝スイッチの ON/OFF**、**Return＝開く・入る**（一覧・スライダー・編集シートを開く・見出しの折りたたみ開閉・
  「その他の文字体系」の開閉）。1つの行が「開く」と「スイッチ」の両方を持つ（通知のスケジュール行）ときも例外にならない。
- 表示画面のキーボードのトグル・学習設定の有効化/「声を分けない」のトグルも **Space だけ**に直す（Phase 1/2 の変更）。
- 一覧モーダルの中の Return/Space＝選んで閉じる は変えない（`DeckPickerModal` などアプリ全体の流儀）。

### 一覧

| 項目 | 操作 |
|---|---|
| 毎日のリマインダー（大元のカード） | **カード全体で1フォーカス**（枠はカードの縁）。Space＝ON/OFF、OS が未許可のときだけ Return＝iOS の設定アプリ（注意行のタップと同じ）。注意行に2つ目のフォーカスは作らない（実機確認で「大元が OFF」の注意行にも止まっていたのを直した） |
| スケジュールの各行 | **Return＝編集シート／Space＝有効/無効／Delete＝削除（確認あり）** |
| 「スケジュールを追加」 | Return。**画面のどこでも N＝追加**（一覧の新規＝N の流儀。上限 5 件に達したら何もしない） |

- **追加は N**（新規デッキ/カード/タグ/土台と同じ「一覧に1件作る」）。カード編集のブロック追加は **A のまま**
  （押すとすぐ作るのではなく種類を選ぶメニューを開く＝性質が違う・手の覚え直しを避ける）。
- 削除の確認は Esc／タップで閉じる（削除系なので Return は割り当てない）。

### 編集シート（下から出る面・`ScheduleModal`）

開いている間は一覧側がキーを手放し、シートが受け持つ。J/K で止まるのは上から：

| 項目 | 操作 |
|---|---|
| 時 | H/L＝1時間・⇧H/⇧L＝3時間（23 の次は 0 に回り込む） |
| 分 | H/L＝1分・⇧H/⇧L＝10分（59 の次は 00。**時は変わらない**＝回転式ピッカーの列と同じ） |
| 時・分（数字） | **0〜9 で直接入力**（24時間表記）：1桁目で即その値・1.5秒以内の2桁目で2桁（範囲を超えるなら新しい1桁目）。時を2桁打ち終えたら（または 3〜9 を打ったら）分へ移る＝時で `0730` と打てば 07:30 |
| 曜日 | 1〜7＝表示されている並び順の曜日を ON/OFF |
| ラベル | Return＝入力欄にカーソル（Return＝完了で外れてキー操作に戻る） |
| 目標未達成のときだけ通知 | Space（目標 OFF のときは従来どおり操作できない） |

シート全体：**S＝保存**（デッキ/タグ編集の S と同じ）・**Delete＝削除**（既存のみ・確認あり）・**Esc＝閉じる**
（保存しない＝背景タップと同じ。ラベルの入力中はまずカーソルを外す）。

- **ピッカーの列の上に枠を重ねない**（12時間表記の言語は列が3つ＝時・分・午前/午後、右から左の言語は並びが逆で、
  列の位置はアプリから分からない）。代わりに**時刻にフォーカスしている間だけ、ピッカーの下に自前の「07 : 30」を出し、
  動かしている側の数字にだけ枠を付ける**（アプリが描く文字なので必ず正しい位置に付く）。
- **曜日にフォーカスしている間だけ、各曜日の下に押す数字（1〜7）を出す**（タップで使う人の見た目は変えない）。
- 回転式ピッカーは iOS の部品でキー操作できないので、値を直接動かす。
- シートには入力欄があるので**矢印は iPhone のみ登録**（iPad は H/L・J/K で操作する）。

## 設計判断

### 選択肢の左右は端で止める（循環しない）

フィルター切替（ホーム/学習/統計）は循環するが、設定の選択肢は「小 → 中 → 大」「ライト → ダーク → システム」
のように**並びに意味がある**。端から反対の端へ跳ぶより止まるほうが直感に合う。

### キーボードのトグルはキーで OFF にしてよい（案 a・2026-09-25 合意）

OFF にした瞬間にキー操作が全部止まり、戻すにはタップが要る。検討した案：

- **(a) そのまま切り替える ← 採用**
- (b) キーで OFF にするときだけ確認ダイアログ
- (c) キーでは OFF にできない

青枠の行で明示的に押している＝誤操作は起きにくい。(b) はこの行だけ扱いが違い、(c) は
「フォーカスできるのに押しても効かない」＝「オンに見えるのに効いていない」を作る。

### カラーテーマの鍵付き（Pro 限定）は、非 Pro のとき H/L で飛ばす

タップでは paywall へ遷移するが、H/L で送るたびに paywall が開くとキー操作が成立しない。
**非 Pro は無料配色（`FREE_CARD_THEMES`）の間だけを動く。** 鍵付きへはタップで到達できる（従来どおり）。

### 共通の仕組みは `SettingsDetail` に置く

6画面それぞれに J/K・青枠・自動スクロール・Esc の順序を書くと必ず不揃いになる。
`SettingsDetail`（全詳細画面の共通シェル）に**フォーカス管理**を持たせ、各行は
「左右」「決定」「直接選択」のハンドラを登録するだけにする。`SegmentedCard` とトグル行は
フォーカス対応（`focused` の見た目＋ハンドラの登録）を内蔵させる。

⚠️ `SettingsDetail` の `suspendKeys`（自前で Esc を持つモーダルを出す画面用）はフォーカス系のキーにも効かせる
（モーダル表示中に背後の J/K・H/L が動かないように）。

## 落とし穴（実装前に潰す）

- **`useKeyCommands` の参照カウント**：詳細画面の J/K と、`LanguagePickerModal` の J/K が同時に登録される。
  モーダル側は `active=visible`、親は `suspendKeys` で**担当を1つにする**（CLAUDE.md「`useKeyCommands` の第2引数」）。
- **文字サイズを変えるとレイアウトが変わる**：フォーカス中の行の位置がずれるので、自動スクロールは
  変更後のレイアウトで測り直す（`onLayout` で控えた Y を使う＝`DeckStagesModal` と同じ方式）。
- **テーマ切替で全画面が再描画される**：フォーカス（index／id）が state として残ることを確認する。
- **Esc の二重発火**：`SettingsDetail` の既存 Esc（escStack → 戻る）とフォーカス解除を**同じハンドラ**に入れる
  （別フックで登録すると両方発火する）。
