# 053 設定の詳細画面のキーボード操作

**フェーズ:** Phase 1（共通の仕組み＋表示）→ Phase 2 以降（1画面ずつ）
**ステータス:** Phase 1 完了（実機確認済み 2026-09-25）／Phase 2 以降 未着手
**要ネイティブ再ビルド:** 不要（JS のみ）

**被依存:** なし

## 概要

設定タブの一覧は J/K（フォーカス）と Return（開く）に対応済み、詳細画面は Esc/B（戻る）だけに
対応している。詳細画面の**中の設定項目**もキーボードで操作できるようにする。

対象の詳細画面は6つ：表示・学習・通知・iCloud 同期・データ・同期の復元（`app/settings/*.tsx`）。
**表示画面から1画面ずつ**進める。

---

## 方針転換（CLAUDE.md の更新が要る）

CLAUDE.md の設定タブの項に「**値の変更はタップ限定（誤操作防止）でキーはナビのみ**」とある。
本チケットで**詳細画面ではキーで値を変えられる**ようにする。

- 誤操作の心配は小さい：**フォーカス（青枠）を当ててから押す2段階**で、押す対象が画面に見えている。
- **設定タブの一覧は従来どおりナビのみ**（一覧には値を変える部品が無い）。
- Phase 1 の完了時に CLAUDE.md の該当箇所を書き換える。

## 共通の操作（全詳細画面）

| キー | 動作 |
|---|---|
| `J` / `K`・`↓` / `↑` | カード（設定項目）単位のフォーカス移動。ヌルサイクル（末尾の次はフォーカスなし）。青枠＋画面外なら自動スクロール（設定タブと同じ見た目） |
| `H` / `L`・`,` / `.`・`←` / `→` | フォーカス中の項目の値を左右に動かす（項目が左右を持つときだけ） |
| `1`〜`n` | フォーカス中の選択肢型の項目で直接選ぶ（上部ブロックのフィルター 1〜4 と同じ流儀） |
| `Return` / `Space` | フォーカス中の項目の「決定」＝トグルの切替・一覧を開く |
| `Esc` | インライン説明（escStack）→ **フォーカス解除** → 戻る（設定タブと同じ「フォーカスがあれば外す」） |
| `B` | 戻る（従来どおり直接戻る） |
| `?` | ショートカット一覧（詳細画面ごとの一覧を新設） |

- **矢印は iPad でも登録する**（詳細画面に文字の入力欄が無い＝CLAUDE.md の「編集が無い画面は両方で登録」）。
  ⚠️ 入力欄を持つ詳細画面が出てきたら、その画面だけ iPhone のみ登録に落とす（学習セッション・エディタと同じ扱い）。
- **フォーカスが無いときは H/L・数字・Return/Space は何もしない。**

## 表示画面（Phase 1）

| 項目 | 部品 | 操作 |
|---|---|---|
| テーマ | `SegmentedCard`（3択） | H/L 等で左右・`1`/`2`/`3` で直接 |
| 文字サイズ | 同上 | 同上 |
| 初期フィルター | 同上（ⓘ あり） | 同上。ⓘ はタップのみ（「ⓘ＝指の操作」の規約） |
| 表示言語 | 行 → `LanguagePickerModal` | `Return`/`Space` で開く → 一覧内は `J`/`K` で移動・`Return`/`Space` で選んで閉じる・`Esc` で閉じる（`DeckPickerModal` と同じ単一選択の流儀） |
| カラーテーマ | 横スクロールの見本 | H/L 等で左右。選択中の見本が見えるよう横スクロールを追従させる |
| キーボード | トグル（`AppSwitch`） | `Return`/`Space` で切替 |

## 設計判断

### 選択肢の左右は端で止める（循環しない）

フィルター切替（ホーム/学習/統計）は循環するが、設定の選択肢は「小 → 中 → 大」「ライト → ダーク → システム」
のように**並びに意味がある**。端から反対の端へ跳ぶより止まるほうが直感に合う。

### キーボードのトグルはキーで OFF にしてよい（案 a・2026-09-25 合意）

OFF にした瞬間にキー操作が全部止まり、戻すにはタップが要る。検討した案：

- **(a) そのまま切り替える ← 採用**
- (b) キーで OFF にするときだけ確認ダイアログ
- (c) キーでは OFF にできない

青枠の行で明示的に押している＝誤操作は起きにくい。(b) はこの行だけ扱いが違い、(c) は
「フォーカスできるのに押しても効かない」＝「オンに見えるのに効いていない」を作る。

### カラーテーマの鍵付き（Pro 限定）は、非 Pro のとき H/L で飛ばす

タップでは paywall へ遷移するが、H/L で送るたびに paywall が開くとキー操作が成立しない。
**非 Pro は無料配色（`FREE_CARD_THEMES`）の間だけを動く。** 鍵付きへはタップで到達できる（従来どおり）。

### 共通の仕組みは `SettingsDetail` に置く

6画面それぞれに J/K・青枠・自動スクロール・Esc の順序を書くと必ず不揃いになる。
`SettingsDetail`（全詳細画面の共通シェル）に**フォーカス管理**を持たせ、各行は
「左右」「決定」「直接選択」のハンドラを登録するだけにする。`SegmentedCard` とトグル行は
フォーカス対応（`focused` の見た目＋ハンドラの登録）を内蔵させる。

⚠️ `SettingsDetail` の `suspendKeys`（自前で Esc を持つモーダルを出す画面用）はフォーカス系のキーにも効かせる
（モーダル表示中に背後の J/K・H/L が動かないように）。

## 落とし穴（実装前に潰す）

- **`useKeyCommands` の参照カウント**：詳細画面の J/K と、`LanguagePickerModal` の J/K が同時に登録される。
  モーダル側は `active=visible`、親は `suspendKeys` で**担当を1つにする**（CLAUDE.md「`useKeyCommands` の第2引数」）。
- **文字サイズを変えるとレイアウトが変わる**：フォーカス中の行の位置がずれるので、自動スクロールは
  変更後のレイアウトで測り直す（`onLayout` で控えた Y を使う＝`DeckStagesModal` と同じ方式）。
- **テーマ切替で全画面が再描画される**：フォーカス（index／id）が state として残ることを確認する。
- **Esc の二重発火**：`SettingsDetail` の既存 Esc（escStack → 戻る）とフォーカス解除を**同じハンドラ**に入れる
  （別フックで登録すると両方発火する）。
