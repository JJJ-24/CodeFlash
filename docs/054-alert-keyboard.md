# 054 アラートのキーボード操作（独占キー）

**フェーズ:** Phase 1（独占の仕組み＋アラート部品）→ Phase 2（画面ごとの抑止処理の整理・任意）
**ステータス:** Phase 1 完了（実機確認済み 2026-09-25）／Phase 2 完了（実機確認済み 2026-09-25）
**要ネイティブ再ビルド:** 不要（JS のみ）

**被依存:** なし

## 概要

アプリのすべてのアラート（確認・破棄・削除・OK だけ）をキーボードで操作できるようにする。
053 Phase 4 で設定の3画面だけ有効にした「J/K で選んで Return で実行（最初は未選択）」を全アラートへ広げる。

| 部品 | 使っている場所（2026-09-25） |
|---|---|
| `ConfirmModal`（選択肢が複数） | 12ファイル（学習セッション・デッキ/カード編集・ペイウォール・`_layout.tsx` の同期の競合通知ほか） |
| `DiscardConfirmModal`（保存/破棄。中身は `ConfirmModal`） | 入力系の6画面 |
| `ConfirmDeleteModal`（削除ボタン1つ） | 13ファイル（一覧・編集・ブロック削除・土台の一覧・画像ライブラリほか） |
| `InfoModal`（OK だけ） | 19ファイル |

---

## 問題：裏の画面のキーを止める処理が画面ごと

アラートの表示中に裏の画面の J/K・Return を止める処理（`active` ゲート・`blockNav`・`suspendKeys`）は画面ごとに
書かれている。アラートに J/K・Return を持たせると、止め忘れている箇所で**二重に反応する**（ボタンを選ぶ J/K で
裏のフォーカスも動く）。`_layout.tsx` の同期の競合通知は**どの画面の上にも出る**ので、裏の画面側で止める手段が無い。

## 解決：独占（exclusive）登録

- `lib/useKeyCommands.ts` に **`useExclusiveKeyCommands(specs, active)`** を足す。これで登録した側が表示されている間は、
  **ほかの全登録のハンドラが反応しない**（イベントの配送時に弾く）。重なったときは**最後に有効になったもの（一番上）だけ**が反応する。
- アラートの部品が使い、**J/K・Return・Esc を自分で受け持つ**。裏の画面が止め忘れていても二重にならない＝
  **画面ごとの確認なしで全アラートに行き渡る**。画面ごとの抑止処理は残っていても害は無い（Phase 2 で整理）。
- **画面のフォーカスに依存しない**（`useFocusEffect` ではなく `useEffect` で登録）＝画面の外（`_layout.tsx`）でも使える。
  アラートは表示中しか登録しないので、フォーカス連動は不要。
- ネイティブ登録の参照カウント（`acquireKeyCommands`/`releaseKeyCommands`）はそのまま使う。
- **裏でカーソルが入っている入力欄は、アラートを出す前に外す**（`lib/alertFocus.ts` の `useAlertPresence`）。外さないと入力欄が
  first responder のまま残り、キーが入力欄に吸われてアラートに届かない（実機確認で発覚：カード編集でブロック編集中に
  削除・閉じるを押すと J/K も Esc も効かず、J/K は裏の入力欄に文字として入った）。
- **外したときだけ表示を約0.1秒遅らせる**。カーソルを外すとブロックが編集中の見た目から戻る（入力欄が片付き装飾パレットも消える）。
  それとアラートの表示が重なると、画面の大枠が一瞬横へずれるちらつきが出た（実機確認で発覚）。
- **キャンセル（Esc・背景のタップ・OK だけのアラートの OK）で閉じたときだけ元の編集へ戻す**（`restoreAfterAlert`）。
  **選択肢を実行したときは戻さない**（`forgetAfterAlert`＝削除でブロックが消える・破棄/保存で画面が閉じていく途中にキーボードが出るため）。
  修正前はタップでキャンセルすればカーソルが残っていたので、その動きを保つ（2026-09-25 合意）。
- ⚠️ **カード編集のブロックは編集をやめると入力欄そのものが消える**（`TextBlockItem`/`CodeBlockItem` は編集中だけ入力欄を置く）ので、
  入力欄へ直接カーソルを戻せない（最初の実装はこれで戻らなかった）。`BlockEditor` が `registerAlertRestoreProvider` で
  「編集していたブロック」を渡し、テキスト・コードとも `restoreTrigger` で最後のカーソル位置のまま再開する。
  ⚠️ **入力欄を作る前に最後の選択を `selection` に渡す**（実機確認で発覚：渡さないとテキストは前回の編集開始時の位置で
  作られてから移る＝カーソルが一瞬末尾に出る、コードは末尾のままになる。コードは `useInsertPair` の `restoreSelection`）。常にある入力欄は直接フォーカスを戻す。控えは最初のアラートが開くときに取り直す。

## 操作

| 部品 | 操作 |
|---|---|
| 確認（`ConfirmModal`）・破棄（`DiscardConfirmModal`） | J/K で選択肢を選ぶ・Return で実行・Esc で閉じる。**開いた時点では未選択** |
| 削除（`ConfirmDeleteModal`） | 同上。**ボタンが1つでも「J/K で選んでから Return」**（Return 1回で消えないように） |
| OK だけ（`InfoModal`） | Return／Esc で閉じる（画面ごとに書いていた Return＝OK を部品に集める） |

- **Esc は各アラートの `onClose` を呼ぶだけ**。閉じたときの後始末（目標 OFF の確認＝完全キャンセル等）は `onClose` にあるので挙動は変わらない。
  これまで画面側の Esc（階層ディスマス）が閉じていた箇所も、どれも `onClose` と同じ「閉じる」だった。
- **矢印（↑/↓）は iPhone だけ**。アラートはカードエディタ・学習セッションの上にも出るので、iPad で矢印を登録すると
  キャッシュが残って編集中のカーソル移動を奪う（CLAUDE.md の「iPad の落とし穴」）。iPad は J/K で選ぶ。
- 053 Phase 4 の `keyboard` prop は**既定で有効**になるので撤去する。
- **未選択に戻す判定は `actions` の参照ではなく中身（タイトル・本文・ボタンの文言）**＝学習セッションはタイマーで毎秒再描画され、
  `actions` をその場で作る呼び出しが多い（参照で判定すると選択が毎秒外れる）。
- CLAUDE.md の「削除/破棄の確認は Return を割り当てない」は、**未選択から始めて選んでから Return**に改める
  （規則の狙い＝連打でうっかり実行しない、は選ぶ操作が必ず挟まることで保つ）。
