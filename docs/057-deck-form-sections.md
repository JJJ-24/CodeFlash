# 057 デッキ新規・編集画面を見出しで区切り、開くだけの行を1行形式に詰める

**フェーズ:** Phase 1
**ステータス:** Phase 1 完了（実機確認済み 2026-09-26）
**要ネイティブ再ビルド:** 不要（JS のみ）
**依存:** 051/052（読み上げの行）・044/045（土台の行）・055（J/K のフォーカス）

---

## 概要

デッキの新規・編集画面は項目が増えて縦に長くなっていた（9項目・非 Pro は7項目）。
**1画面のまま**「基本／読み上げ／コード実行」の見出しで区切り、開くだけの行を設定画面と同じ1行形式（左に項目名・右に要約と ＞）に詰める。

| 見出し | 項目 |
|---|---|
| 基本 | デッキ名・説明・アイコン・カラー・アーカイブ（編集のみ） |
| 読み上げ | 読み上げ（スイッチ）・読み上げの設定（1枚のカード） |
| コード実行（Pro のみ） | HTML/CSS 土台・SQL 初期化（1枚のカード） |

- **⇧J/⇧K＝前後のセクションの先頭の項目へ**（学習設定の見出し移動と同じ・端では巡回）。見出し自体は J/K の止まり先にしない（開閉できない見出しに止まっても何もできない）。
- 文字キー・J/K・Return/Space・`,`/`.` は 055 のまま。

## タブ分け（「基本」「読み」「土台」）を不採用にした理由（2026-09-26）

1. 項目数に対してタブが重い：「読み」「土台」は2行ずつしかなく、スクロールが減る代わりに設定の要約（「英語」「土台 2件」）が別タブに隠れる。
2. 「土台」タブは Pro 専用＝非 Pro では空のタブになるか、Pro かどうかでタブの数が変わる（カード編集の表/裏/メモのような「いつも同じタブ」にならない）。
3. キーが2か所で衝突する：タブ切替の H/L と `H`＝HTML/CSS 土台、`,`/`.` と 055 のカラー送り。文字キーには自動のタブ切替も要る。
4. カード編集のタブは同じ種類の中身（面）の切替で、分類の切替ではない。アプリ内で分類を持つ画面（学習設定）は見出し＋1本のスクロール。

項目がさらに増えて見出しでも長すぎるようになったら、そのときにタブを再検討する。

## 実装

- 共通部品 `components/deck/DeckFormParts.tsx`：`DeckFormSectionTitle`・`DeckFormCard`（`SettingsFocusGroup`＝中の行の位置を控える）・
  `DeckFormNavRow`（1行形式）・`DeckFormToggleRow`（スイッチ＋ⓘ）・`DeckFormDivider`。新規・編集の両画面で使う。
- ⚠️ 行はカードの**直接の子**に置く（055 の `SettingsFocusGroup` の規則）。
- 読み上げ OFF／アプリ OFF の淡色と注記、非 Pro の鍵、Pro だけ行ごと出す土台、の各規則は 051/052/044 のまま。
