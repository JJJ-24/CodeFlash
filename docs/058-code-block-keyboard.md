# 058 コードブロックの中身（言語・実行・土台・初期化・プレビュー）をキーで操作する

**フェーズ:** Phase 1〜4
**ステータス:** Phase 1〜4 完了（実機確認済み 2026-09-28）
**要ネイティブ再ビルド:** 不要（JS のみ）
**依存:** 034（ネイティブ UIKeyCommand）・053/055/056（J/K のフォーカス・Return＝開く／Space＝スイッチ）・040/041/044/045（土台・プレビュー）

---

## 概要

カード編集・新規作成のコードブロックでキーで届くのは「フォーカス → 編集（E/Return）・実行（R）・削除（Delete）」だけだった。
言語の変更・実行トグル・HTML/CSS 土台・SQL 初期化・デッキ土台の選択・実行前プレビューのトグル・プレビュー枠の操作は、すべてタップでしかできない。
これをキーでも届くようにする。編集画面が終わったら学習画面のプレビュー枠も同じにする。

## 方針（2026-09-28 合意）

1. **どのコードブロックにもあるもの（言語・実行トグル）は止まり先にしない**＝ブロックにフォーカスした状態の直接キー。
   止まり先にするとコードブロック1つを通るのに毎回3回押すことになり、今の「J でブロックからブロックへ」が崩れる。
2. **あったり無かったりするもの（土台・初期化・デッキ土台の選択・実行前プレビューのトグル）は、表示されているときだけ J/K の止まり先**。
   無いブロックは今までどおり J 1回で次へ。ブロック単位で飛ぶのは ⇧J/⇧K（057 のセクション送り・053 の学習設定と同じ）。
3. **H/L・`,`/`.` は使わない**＝表/裏/メモのタブ切替で定着しており、止まり先によって意味が変わると押すまで結果が読めない。
   横の選択（デッキ土台が2つ以上のチップ）は Return で一覧を開いて選ぶ。
4. 「Return で中へ入り、中で J/K」の2段方式は不採用（053 と同じ理由＝段で Esc の意味・見た目が変わる）。

## Phase 1：言語と実行トグル（編集モード）

| キー | ブロックにフォーカス中 |
|---|---|
| **G** | 言語の一覧を開く（中は J/K・Return/Space＝選んで閉じる・Esc＝閉じる。開いたときは今の言語） |
| **Space** | 実行トグル（実行できる言語のときだけ。056 のアーカイブ欄の Space と同じ「Space＝スイッチ」） |

- 言語の一覧（タップで開くものと同じ）が出ている間はエディタのキーを手放す（タップで開いたときも）。
  ⚠️ **一覧の矢印は iPhone のみ**＝カードエディタの上に出るので、iPad で登録すると矢印のキャッシュが残り、編集中のカーソル移動を奪う（054 のアラートと同じ）。

## Phase 2：土台・初期化の止まり先（編集モード）

巡回：**ブロック本体 → そのブロックの止まり先（画面の上から順）→ 次のブロック**。K は逆順（前のブロックの最後の止まり先へ）。
⇧J/⇧K はブロック本体だけを巡回する（止まり先を飛ばす）。並べ替えモードはブロックだけ（056 と同じ）。

| 止まり先（表示されているときだけ） | Return | Space |
|---|---|---|
| 初期化SQL（ブロック固有） | 開いて入力開始（Esc で青枠へ戻る） | — |
| デッキ土台の選択（HTML・SQL）／土台1つ＝トグル | — | ON/OFF |
| デッキ土台の選択（HTML・SQL）／土台2つ以上＝チップ | 一覧を開いて選ぶ | — |
| HTML/CSS 土台（ブロック固有） | 開いて入力開始（Esc で青枠へ戻る） | — |
| 実行前プレビュー（html） | — | ON/OFF |

- 止まり先にいる間も **R＝そのブロックを実行・E＝本文を編集** は効く（ブロック単位の操作）。**Delete は何もしない**（056 の末尾と同じ＝設定を選んでいるつもりでブロック削除の確認に繋がらないように）。
- Space の実行トグル・G は**ブロック本体にフォーカス中だけ**（止まり先では Space がその止まり先のスイッチになる）。
- フォーカスした項目は**画面の真ん中へ送る**（ホーム・カード一覧・設定と同じ `centeredScrollY`）。
  056 の末尾の項目（＋ブロック追加・タグ・アーカイブ）も同じにそろえた＝以前は「画面外なら上下 8pt だけ見える位置まで」で、
  最下部に張り付いて次の項目が J を押すまで見えなかった（2026-09-28 指摘）。ブロック本体は従来どおり上寄せ（上端 −80）。

## Phase 3：プレビュー枠（編集モード）／Phase 4：学習画面のプレビュー枠（2026-09-28 合意）

当初案は「プレビュー枠も止まり先にして Return＝⛶・Space＝[プレビュー｜ソース]」だったが、
学習画面では Space がカードの表裏反転なので同じ割り当てにできない。**止まり先にはせず、両画面で同じ直接キー**にした
（止まり先が1つ減るので J/K も短くなる）。

| キー | 動作 | ボタン |
|---|---|---|
| **V** | [プレビュー｜ソース] 切替（View） | ソースのタブが出ているときだけ |
| **⇧F** | ⛶ 全画面（学習画面の F＝カードの全画面の仲間） | ⛶ が出ているときだけ（Pro・web 系） |
| **⇧R** | ⟲ 実行前に戻す（R＝実行の逆）。console 系の言語では実行結果の ✕ と同じ | ⟲ か実行結果が出ているときだけ |

- 対象はカード編集＝**フォーカス中のブロック**（止まり先にいても効く）、学習画面＝**J/K で選択中のブロック**。
- 実装は `ExecutionOutput` の `keyTrigger`（`{ action, n }`）。**ボタンと同じ条件のときだけ効かせる**＝見えていないボタンを押したことにしない。
- ⚠️ `keyTrigger` は **`undefined`＝このブロックは対象外／`null`＝対象だがまだ押されていない**。対象外→対象に変わった瞬間（J/K で選ばれた・マウント）の値は発火しない
  ＝前に別のブロックへ押したキーが、選び直した途端に効くのを防ぐ（学習画面は1つの値を選択中のブロックへ渡すため）。
- 全画面モーダルが開くと、両画面とも既存の仕組み（`InteractivePreviewContext`）で背後のキーが止まる。
- **全画面モーダルの中**（2026-09-28 追加）：**R＝▶ 実行（再実行）・⇧R＝⟲ 実行前に戻す**（⟲ が出ているときだけ）。インラインの R＝実行・⇧R＝⟲ と同じ意味。
  **ページの keydown とは競合しない（2026-09-28 実機確認）**：入力欄の外で押したキーは、アプリが登録していない `a` も含めて**ページに届いていない**
  （`document.addEventListener('keydown', …)` のページで、ページをタップしてからでも `a` も `r` も反応なし）。
  ＝ R はページから何も奪っていない。入力欄にカーソルがあるときは入力欄が先に受け取る（従来どおり）。
  入力欄の外で keydown を拾う教材が全画面で動かないのは R とは別の既存の制限（改善するなら別件）。
- **全画面の Esc は「ページの入力欄のカーソルを外す → 閉じる」の順**（2026-09-28・アプリの他の画面と同じ順）。
  以前は入力欄にカーソルを入れると R は文字として入力欄に取られ、Esc は全画面ごと閉じるので、実行し直す手段が無かった。
  モーダルの WebView にだけ `EDITING_WATCH_SCRIPT`（focusin/focusout で「文字を打てる要素にカーソルがあるか」を postMessage）を差し込み、
  入力中の Esc は `document.activeElement.blur()` を流すだけにする（サンドボックス本体は無改造）。
- **⌘R＝入力中でも実行**（2026-09-28・案 A＝カーソルを残す）。⌘ 付きのキーは入力欄に取られずアプリに届く（⌘. と同じ）。
  - カード編集：編集中のブロック（本文・土台・初期化の欄）を、無ければフォーカス中のブロックを実行。実行結果は元から編集中も出ている。
  - 学習画面：選択中のブロックを、**編集を抜けずに**実行（R・▶ は編集を抜けてから実行）。学習画面は編集中は実行結果を隠すので、⌘R で実行したときだけ編集中も出す（`showOutputWhileEditing`・編集を終える／始め直すと戻す）。
  - ⚠️ 学習画面の ⌘R は**ブロックを選び直さない**（`onSelectRequest`/`onRunRequest` を呼ばない）。選び直すと学習画面が「相手の面の編集を終わらせる」処理で
    キーボードを閉じて編集中フラグ（`codeEditingRef`）も倒すため、カーソルが外れ、その後の ⌘.（Esc）が「編集中」と分からず学習画面ごと戻っていた。
    念のため、実行中〜完了 0.8 秒後までに入力欄のフォーカスが外れたら1回だけ入力欄へ戻す。
  - ⚠️ ⌘R の値（`runKeepEditTrigger`）は R と同じ場面（J/K・タップでの選び直し・カード送り・表裏）で 0 に戻す＝残すと、次に選ばれたブロックが受け取った瞬間に実行する。
  - 全画面プレビュー：▶ と同じ。ページを作り直すので、入力欄のカーソルは消える（ページごと描き直すため避けられない）。
  - 案 B（▶ と同じく編集を抜けて実行）は不採用＝入力中でも実行できることがこのキーの存在理由で、抜けるなら Esc → R と変わらない。

## 付随の修正：スクロールを「必要な分だけ」にする（2026-09-28・iPad で指摘）

- **実行後の自動スクロール**：以前は「ブロック末尾 −300」（学習画面は＋キーボード）へ送っていたため、エラー＋HTML プレビューのブロックでは
  プレビューの下まで進み、上にあるエラーが半分隠れた。**実行結果の先頭〜ブロック末尾**を必要な分だけ見せ、収まらなければ**先頭（エラー）を優先**する。
  実行結果の先頭は、`ExecutionOutput` の直前に置いた高さ 0 の目印 View の `onLayout` で測る（レイアウトは変えない）。
- **Return（E）で編集を始めたときのスクロール**：以前は常に「ブロック末尾を画面最下部へ」送っていたため、画面の上の方にあるブロックでも最下部まで動いた
  （iPad＋ハードキーボードはキーボードが出ないので特に目立つ。先頭付近と末尾のブロックだけ動かないのはスクロールの端で止まっていただけ）。
  **カーソル（末尾の行）が隠れるときだけ**見える位置までスクロールする。カード編集は本文の欄＋記号パレットまで（下の実行結果・プレビューは見せない）、
  学習画面はブロック末尾まで（編集中は実行結果を隠すので末尾がカーソルの近く）。収まらないほど長いブロックは末尾を優先。
- 学習画面は今のスクロール位置を `BlocksView` の `scrollYRef`（`frontScrollYRef`/`backScrollYRef`）で受け取る。
- ⚠️ 編集を始めると実行結果・プレビューを隠す（学習画面）ので、ブロックが画面の下端近くにあるとコンテンツが縮んでスクロール位置が押し戻され、少し動いて見えることがある（避けられない）。
